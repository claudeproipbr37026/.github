<p>排名榜是别人写的，线路得自己跑。同一份榜单，在洛杉矶好用，搬到国内某个城市可能完全不是那回事；这个月排第一，下个月上游调整就掉到中游。与其信榜单，不如做一组小规模对照实验：三条线路、三轮测试、一次只动一个变量，两周就能得出属于你自己的排序。</p>

<h2>一、实验怎么设计：一次只动一个变量</h2>
<p>最忌讳的做法是同时换线路、换浏览器、换时段，然后得出「新线路更好」的结论。三个变量一起动，你根本不知道是谁起的作用。正确做法是固定环境、固定测试脚本、固定采样时段，只让线路这一个变量变化。</p>
<h3>三组怎么选</h3>
<p>A 组用你现在正在用的线路，作为基线；B 组选口碑榜上排前面的候选；C 组选一个明确不同价位或不同线路类型的候选。三组同时跑，才有横向可比性。只测一组，得到的是绝对值，没有参照。</p>
<h3>哪些条件必须锁死</h3>
<p>浏览器配置文件、系统时区、测试脚本、采样时间点、测试账号，这五项在整轮实验里都不能变。建议写成一页纸的实验说明，谁执行都照这个来，避免不同人操作引入误差。</p>

<h2>二、第一轮：纯净度对照</h2>
<p>这一轮不看速度，只看出口的「干净程度」。方法是对每条线路的出口地址做三件事：查归属运营商、查是否落在机房段、查历史风险评分。三项都拿数据说话，不靠体感。</p>
<h3>三项查询怎么做</h3>
<p>归属用 ipinfo.io 或 ip-api.com，看 org 与 ASN 字段是否指向本地运营商；机房段用同一接口返回的类型字段判断，出现 hosting、colo、cloud 就要留神；风险评分用 scamalytics 一类站点，看它给出的风险等级和最近一次被标记的时间。三项结果记录在同一行，方便横向比。</p>
<h3>结果怎么读</h3>
<p>三条线路都是住宅段，但评分可能差一个量级。评分偏高的，往往意味着这段地址此前被较多使用过，后续出现额外验证的概率也偏高。这里不做绝对判断，只是把差异记下来，进第三轮售后测试时一起看。</p>

<h2>三、第二轮：延迟与抖动对照</h2>
<img src="/tp.png" alt="三条住宅IP线路延迟与丢包对照测试的数据记录">
<p>这一轮要跑出曲线，而不是一个数字。每条线路在晚八点到十点之间连打三百个包，把延迟序列存下来，看均值、最大值和抖动幅度。三条线在同一时段并行测，避免时段差异干扰。</p>
<h3>指标怎么定义</h3>
<p>均值反映常态，最大值反映最差体验，抖动用标准差或者最大值减均值表示。对话类使用对均值不敏感，对最大值敏感——偶发的一次两秒卡顿，比整体慢五十毫秒更影响体感。</p>
<h3>三条线路的预期差异</h3>
<p>一般来说，本地运营商直连的线路均值低、抖动小；跨运营商转售的线路均值中等，晚高峰抖动明显；共享池拨出的线路均值波动最大。这只是常见规律，你的实测结果可能不同，以数据为准。</p>

<h2>四、第三轮：售后响应计时</h2>
<p>前两轮测的是线路，这一轮测的是人。方法是每条线路各提一次非紧急工单，问一个具体技术问题，比如某城市节点的 ASN 是多少，然后记录三个时间：首次响应、给出有效答复、问题闭环。三个时间加起来，才是真实的售后成本。</p>
<h3>怎么提一次「有效」的工单</h3>
<p>问题要具体、可回答，别问「你们稳定吗」这种没法答的。带上你自己的测试数据截图，说明线路名、时间、现象。愿意认真回的，会问你要 mtr 结果；只会回「已反馈技术」的，基本可以判断层级。</p>
<h3>计时结果怎么用</h3>
<p>把三家的首次响应时间做成一行数据，和价格放一起看。月费便宜一百元但响应要等一天，对一个每天要用的账号来说未必划算。这一轮没有标准答案，取决于你对中断的容忍度。</p>

<h2>五、把三组结果合成一张判断表</h2>

<h2>常见问答</h2>
<h3>没有三条线路，只测一条可以吗？</h3>
<p>答：可以，但要先给自己建一个基线。用现在的线路跑一周数据，再换新线路跑一周，两段数据对比。缺点是时间拉长，中间可能有上游变化干扰。</p>
<h3>榜单完全没用吗？</h3>
<p>答：有用，但只能当候选池。榜单能帮你缩小到三五个名字，最终排序必须自己测。看榜单时留意它有没有写测试方法、测试时段和样本量，这些比名次本身更重要。</p>
<h3>测试会不会影响账号？</h3>
<p>答：用专门的测试账号做线路测试，不要拿主力账号跑。测试期间只做常规访问，不做高频请求，避免给正常账号带来不必要的波动。</p>
<h3>多久需要重测一次？</h3>
<p>答：建议每季度一次，或者在出现明显体感变化时立即重测。上游运营商调整、服务商换池子，都会让半年前的结论失效。</p>

<h2>合规提示</h2>
<p>对照实验应仅在你自己租用或获得书面授权的线路上进行，测试内容限于常规连通性与延迟测量，不得对第三方网络做压力测试或探测。</p>
<p>实验记录中可能包含地址、ASN 等信息，请按内部数据规范保存，避免外泄影响他人网络环境。使用网络服务须遵守所在地法律与平台条款。</p>
